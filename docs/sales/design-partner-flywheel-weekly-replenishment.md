# Flywheel — weekly pipeline replenishment

**Standing rule:** Preserve the IronBoard flywheel **process**; run it **weekly** as pipeline refill — **not** daily as an outreach task.

**Companions:** [Ops surface map](./design-partner-ops-surface-map.md) · [Week-1 Scout](./design-partner-week1-mssp-scout-playbook.md) · [Outreach sequence](./design-partner-outreach-sequence.md) · Mandate 33 (flywheel ≠ Approvals send-ready)

---

## What flywheel is (and isn’t)

| Is | Isn’t |
|----|--------|
| Regional / ICP **research** hopper (`market_prospects`) | Ironleads SUSPECT store |
| Discover → authenticity verify → RESEARCH stage | Path B seats or pipeline $ |
| Feed for **later** Gatekeeper promote | Daily DISPATCH work |

Daily Path B work stays: **Approvals HITL** (Touch 1 / Touch 2) + shortlist §D.

---

## Weekly loop (one session)

**When:** **Friday** each business week (after that day’s HITL Touch 1/2 DISPATCH batch). If Friday is a holiday / no-send day, run the next business day the same week.  
**Time box:** ~30–45 minutes. Stop when you have **0–3** promote-ready candidates — not a long discover binge.

**Why Friday:** send cadence is done for the week; replenishment feeds **next week’s** HITL queue without competing with daily DISPATCH.

1. **Pick one region / beachhead slice** (prefer MSSP/vCISO beachhead D unless operator explicitly expands).
2. **Run flywheel discover + authenticity** (purge synthetic / scaffolding; keep authentic research rows only).
3. **Gatekeeper** each interesting row: Fit · Pain · Buyer access · work email — **no proprietary GRC-platform conflict**.
4. **Promote** only passes into prospect-pool CRM (`MSSP_ENCLAVE` when applicable) → SalesTeam poll → Approvals PENDING.
5. **Queue into next week’s HITL batch** — do not break today’s 6/day send cadence to mass-import research names.
6. **Log** promote outcomes on ICP shortlist §D (company · source=`flywheel-weekly` · date).

**Forbidden in the same session:** inventing Challenger essays from flywheel research; claiming “ready to send” from flywheel names; DISPATCH without Approvals HITL.

---

## Daily vs weekly

| Cadence | Job |
|---------|-----|
| **Daily** | Shortlist due + Approvals DISPATCH (Touch 1/2) + inbound |
| **Weekly** | Flywheel replenishment → Gatekeeper → promote few into next wave |

---

## Done when

- [ ] One weekly session logged (even if zero promotes — “no Gatekeeper pass” is a valid outcome)
- [ ] Any promote has named buyer To + researched open before READY
- [ ] Flywheel rows that failed Gatekeeper stay RESEARCH — not Approvals
